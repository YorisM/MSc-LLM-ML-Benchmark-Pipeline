This solution addresses the four-top-quark classification challenge focusing on maximizing the AUC metric. Here's a detailed explanation of my approach:

## Preprocessing (MyPreprocessor class)

The preprocessing phase is crucial for this physics problem as it deals with sparse, variable-length data from particle collisions:

1. **Feature Selection and Scaling**:
   - I identify and select only valid indices where actual data exists (non-zero object types)
   - Each physical quantity (energy, transverse momentum, pseudorapidity, azimuthal angle) is standardized separately
   - The missing transverse energy (ET_miss) and its azimuthal angle are preserved and scaled
   
2. **Physics-informed Feature Engineering**:
   - **Object Counting**: For each event, I count objects by type, which helps identify the particle content
   - **HT Calculation**: Sum of all jet pT (transverse momentum), a key discriminating variable in high-energy physics
   - **MET/HT Ratio**: Ratio of missing energy to total hadronic energy, useful for identifying events with invisible particles

3. **Data Normalization**:
   - Each feature is normalized using StandardScaler to ensure all features contribute equally to the model
   - Epsilon value prevents division by zero when calculating ratios

## Model Architecture (FourTopClassifier)

The neural network is designed to effectively learn from the high-dimensional, physics-based features:

1. **Residual Network Design**:
   - Implements residual blocks which help with gradient flow in deep networks
   - Each residual block contains two linear layers with batch normalization
   - Skip connections allow the model to learn both simple and complex feature relationships

2. **Multi-layer Structure**:
   - Initial projection to higher dimensionality (256 neurons)
   - Multiple residual blocks to learn complex patterns
   - Gradually decreasing hidden layer sizes (256→256→128→64)
   - Final output layer for binary classification

3. **Regularization Techniques**:
   - Batch normalization to stabilize and accelerate training
   - Dropout (0.3) to prevent overfitting
   - ReLU activation functions for non-linearity

## Training Approach

1. **Optimization Strategy**:
   - Adam optimizer with weight decay for regularization
   - Binary Cross Entropy with Logits Loss (combines sigmoid activation and BCE)
   - Learning rate scheduler (ReduceLROnPlateau) to adaptively reduce learning rate when validation loss plateaus

2. **Training Loop**:
   - 30 epochs for model training (a balance between convergence and runtime constraints)
   - Gradient clipping to prevent exploding gradients
   - Tracks both training and validation metrics (loss and accuracy)

3. **Efficient Computation**:
   - Uses GPU acceleration when available
   - Importance is given to avoid excessive memory usage

## Physics-Informed Decisions

1. **Feature Selection Based on Physics Knowledge**:
   - Four-vectors (E, pT, eta, phi) are the fundamental representation of particles in high-energy physics
   - HT is especially relevant for multi-top events as they produce many high-pT jets
   - Object counting helps identify the jet multiplicity, critical for distinguishing tttt from tt+X backgrounds

2. **Model Design for High-Energy Physics**:
   - The model's depth and width allow it to learn complex correlations between particles
   - Residual connections help capture both local and global event features

## Special Considerations

1. **AUC Optimization**:
   - While I considered implementing a custom AUC loss function (provided in the code), I used BCEWithLogitsLoss for training as it's more stable and converges better, while still producing good AUC results
   - The model implicitly optimizes for AUC by correctly ranking signal vs background probabilities

2. **Runtime and Memory Efficiency**:
   - The preprocessing is designed to be memory-efficient by processing only necessary features
   - The model is relatively compact (< 50 MB) to meet the constraints
   - No extensive hyperparameter tuning is performed to respect the runtime limitations
